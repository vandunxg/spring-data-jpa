[[vector-search]]
= Vector Search

Cùng với sự phát triển của Generative AI, vector database ngày càng được sử dụng rộng rãi trong lĩnh vực database.
Các database này cho phép lưu trữ và query hiệu quả các vector nhiều chiều, phù hợp với những tác vụ như semantic search, hệ thống gợi ý (recommendation systems) và natural language understanding.

Vector search là một kỹ thuật truy xuất dữ liệu tương đồng về mặt ngữ nghĩa bằng cách so sánh các biểu diễn vector (còn gọi là embeddings), thay vì dựa vào các query exact-match truyền thống.
Cách tiếp cận này cho phép xây dựng các ứng dụng thông minh, nhận biết ngữ cảnh (context-aware), vượt ra ngoài khả năng truy xuất dựa trên từ khóa.

Trong bối cảnh Spring Data, vector search mở ra những khả năng mới để xây dựng các ứng dụng thông minh, nhận biết ngữ cảnh, đặc biệt trong các lĩnh vực như natural language processing, hệ thống gợi ý và Generative AI.
Bằng cách mô hình hóa việc query dựa trên vector thông qua các repository abstraction quen thuộc, Spring Data cho phép developer tích hợp liền mạch các database có khả năng xử lý vector dựa trên similarity, với sự đơn giản và nhất quán của programming model Spring Data.

[[vector-search.model]]
== Mô hình Vector

Để hỗ trợ vector search theo cách type-safe và idiomatic, Spring Data giới thiệu các abstraction cốt lõi sau:

* <<vector-search.model.vector,`Vector`>>
* <<vector-search.model.search-result,`SearchResults<T>` và `SearchResult<T>`>>
* <<vector-search.model.scoring,`Score`, `Similarity` và các scoring function>>

[[vector-search.model.vector]]
=== `Vector`

Type `Vector` biểu diễn một embedding số học n chiều, thường được tạo bởi các embedding model.
Trong Spring Data, type này là một wrapper nhẹ quanh một mảng số thực dấu phẩy động, giúp đảm bảo tính bất biến và nhất quán.
Type này có thể được dùng làm input cho search query hoặc làm một property của domain entity để lưu biểu diễn vector tương ứng.

====
[source,java]
----
Vector vector = Vector.of(0.23f, 0.11f, 0.77f);
----
====

Việc dùng `Vector` trong domain model loại bỏ nhu cầu làm việc trực tiếp với các raw array hoặc list số, cung cấp một cách xử lý vector data type-safe và giàu tính biểu đạt hơn.
Abstraction này cũng cho phép tích hợp dễ dàng với nhiều vector database và thư viện khác nhau.
Nó cũng cho phép triển khai các tối ưu hóa đặc thù của vendor, chẳng hạn như binary vector hoặc quantized vector, vốn không map với biểu diễn floating-point tiêu chuẩn (`float` và `double` theo https://en.wikipedia.org/wiki/IEEE_754[IEEE 754]).
Một domain object có thể có một property vector dùng cho similarity search.

[[vector-search.model.search-result]]
=== Kết quả Search

Type `SearchResult<T>` đóng gói kết quả của một vector similarity query.
Nó bao gồm cả domain object khớp với query và một relevance score cho biết mức độ khớp với query vector.
Abstraction này cung cấp một cách có cấu trúc để xử lý việc xếp hạng result và giúp developer dễ dàng làm việc với cả dữ liệu lẫn mức độ liên quan trong ngữ cảnh của nó.

ifdef::vector-search-repository-include[]
include::{vector-search-repository-include}[]
endif::[]

Trong ví dụ này, method `searchByCountryAndEmbeddingNear` trả về một object `SearchResults<Comment>`, chứa một list các instance `SearchResult<Comment>`.
Mỗi kết quả bao gồm entity `Comment` khớp và relevance score của nó.

Relevance score là một giá trị số cho biết mức độ tương đồng giữa vector được match và query vector.
Tùy thuộc vào việc score đó biểu diễn khoảng cách (distance) hay độ tương đồng (similarity), score cao hơn có thể mang nghĩa khớp gần hơn hoặc xa hơn.

Scoring function dùng để tính score này có thể thay đổi tùy theo database, index hoặc input parameter bên dưới.

[[vector-search.model.scoring]]
=== Score, Similarity và Scoring Function

Type `Score` chứa một giá trị số cho biết relevance của một search result.
Nó có thể được dùng để xếp hạng kết quả dựa trên độ tương đồng với query vector.
Type `Score` thường là một số thực dấu phẩy động, và cách diễn giải của nó (score cao hơn tốt hơn hay thấp hơn tốt hơn) phụ thuộc vào similarity function cụ thể được sử dụng.
Score là dữ liệu phát sinh từ vector search và không bắt buộc phải có để một thao tác search thành công.
Giá trị score không thuộc domain model, vì vậy phù hợp nhất khi được biểu diễn dưới dạng out-of-band data.

Nói chung, một Score được tính bởi một `ScoringFunction`.
Scoring function thực tế dùng để tính score này có thể phụ thuộc vào database bên dưới và có thể được lấy từ một search index hoặc các input parameter.

Spring Data khai báo các constant cho những function thường dùng như:

Euclidean Distance:: Tính khoảng cách đường thẳng trong không gian n chiều bằng căn bậc hai của tổng bình phương các hiệu số.
Cosine Similarity:: Đo góc giữa hai vector bằng cách tính Dot product trước, sau đó chuẩn hóa kết quả bằng cách chia cho tích độ dài của chúng.
Dot Product:: Tính tổng các phép nhân theo từng phần tử.

Việc lựa chọn similarity function có thể ảnh hưởng đến cả hiệu năng lẫn semantics của search, và thường được quyết định bởi database hoặc index đang được sử dụng.
Spring Data thích ứng với các khả năng của native scoring function của database và việc score đó có thể được dùng để giới hạn result hay không.

[[vector-search.methods]]
== Các method của Vector Search

Vector search method được định nghĩa trong repository theo cùng quy ước với các Spring Data query method tiêu chuẩn.
Các method này trả về `SearchResults<T>` và yêu cầu một parameter `Vector` để xác định query vector.
Việc triển khai thực tế phụ thuộc vào internals của data store bên dưới và các khả năng vector search mà data store cung cấp.

NOTE: Nếu bạn mới làm quen với Spring Data repository, hãy chắc chắn bạn đã nắm được xref:repositories/core-concepts.adoc[các khái niệm cơ bản về định nghĩa repository và query method].

Thông thường, bạn có thể khai báo một search method theo hai cách:

* Query Derivation
* Khai báo String-based Query

Vector search method phải khai báo một parameter `Vector` để xác định query vector.

[[vector-search.method.derivation]]
=== Derived Search Methods

Một derived search method dùng tên method để suy ra query.
Vector search hỗ trợ các keyword sau để thực hiện vector search khi khai báo search method:

.Các keyword predicate của query
[options="header",cols="1,3"]
|===============
|Từ khóa logic|Các biểu thức keyword
|`NEAR`|`Near`, `IsNear`
|`WITHIN`|`Within`, `IsWithin`
|===============

include::{vector-search-method-derived-include}[]

Derived search method thường dễ đọc và dễ bảo trì hơn vì dựa vào tên method để diễn đạt ý định của query.
Tuy nhiên, một derived search method yêu cầu bạn khai báo `Score`, `Range<Score>` hoặc `ScoringFunction` làm tham số thứ hai cho keyword `Near`/`Within` để giới hạn result search theo score của chúng.

[[vector-search.method.string]]
=== Annotated Search Methods

Annotated method cung cấp toàn quyền kiểm soát semantics và parameter của query.
Khác với derived method, chúng không dựa vào quy ước đặt tên method.

ifdef::vector-search-method-annotated-include[]
include::{vector-search-method-annotated-include}[]
endif::[]

Với quyền kiểm soát tốt hơn đối với query thực tế, Spring Data có thể đưa ra ít giả định hơn về query và parameter của nó.
Ví dụ, việc normalization của `Similarity` sử dụng native score function trong query để chuyển similarity đã cho thành một giá trị predicate của score và ngược lại.
Nếu một annotated query không định nghĩa, chẳng hạn, score thì giá trị score trong `SearchResult<T>` trả về sẽ là zero.

[[vector-search.method.sorting]]
=== Sorting

Theo mặc định, kết quả search được sắp xếp theo score của chúng.
Bạn có thể ghi đè việc sắp xếp bằng cách dùng parameter `Sort`:

.Sử dụng `Sort` trong Repository Search Method
====
[source,java]
----
interface CommentRepository extends Repository<Comment, String> {

  SearchResults<Comment> searchByEmbeddingNearOrderByCountry(Vector vector, Score score);

  SearchResults<Comment> searchByEmbeddingWithin(Vector vector, Score score, Sort sort);
}
----
====

Lưu ý rằng custom sorting không cho phép biểu diễn score như một sorting criteria.
Bạn chỉ có thể tham chiếu đến các property của domain.
