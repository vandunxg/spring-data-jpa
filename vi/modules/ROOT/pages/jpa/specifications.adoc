[[specifications]]
= Specifications

Criteria API của JPA cho phép bạn xây dựng query theo cách lập trình (programmatically).
`Specification` của Spring Data JPA cung cấp một API nhỏ gọn, tập trung để biểu diễn predicate trên entity và tái sử dụng chúng giữa các repository.
Dựa trên khái niệm specification từ cuốn sách "`Domain Driven Design`" của Eric Evans, specification tuân theo cùng ngữ nghĩa đó, cung cấp một API để định nghĩa criteria bằng JPA.
Để hỗ trợ specification, bạn có thể mở rộng repository interface của mình bằng interface `JpaSpecificationExecutor`, như sau:

[source, java]
----
public interface CustomerRepository extends CrudRepository<Customer, Long>, JpaSpecificationExecutor<Customer> {
}
----

Một specification là một predicate trên một entity, được biểu diễn bằng Criteria API.
Spring Data JPA cung cấp hai entry point:

* <<predicate-specification,`PredicateSpecification`>>: Một interface linh hoạt, không phụ thuộc vào loại query, được giới thiệu cùng với Spring Data JPA 4.0.
* <<specification-interfaces,`Specification`>> (và `UpdateSpecification`, `DeleteSpecification`): Các biến thể gắn với một loại query cụ thể.

[[predicate-specification]]
== PredicateSpecification

Interface `PredicateSpecification` được định nghĩa với tập dependency tối thiểu, cho phép composition linh hoạt về mặt functional:

[source, java]
----
public interface PredicateSpecification<T> {
  Predicate toPredicate(From<?, T> from, CriteriaBuilder builder);
}
----

Specification có thể dễ dàng được dùng để xây dựng một tập predicate có khả năng mở rộng và sử dụng với `JpaRepository`, loại bỏ nhu cầu khai báo một query (method) cho mỗi tổ hợp cần thiết, như trong ví dụ sau:

.Specification cho Customer
====
[source,java]
----
class CustomerSpecs {

  static PredicateSpecification<Customer> isLongTermCustomer() {
    return (from, builder) -> {
      LocalDate date = LocalDate.now().minusYears(2);
      return builder.lessThan(from.get(Customer_.createdAt), date);
    };
  }

  static PredicateSpecification<Customer> hasSalesOfMoreThan(MonetaryAmount value) {
    return (from, builder) -> {
      // build predicate for sales > value
    };
  }
}
----

Type `Customer_` là một metamodel type được sinh ra bằng JPA Metamodel generator (xem link:$$https://docs.jboss.org/hibernate/jpamodelgen/1.3/reference/en-US/html_single/#whatisit$$[tài liệu của Hibernate implementation để xem ví dụ]).
Vì vậy, biểu thức `Customer_.createdAt` giả định rằng `Customer` có một attribute `createdAt` kiểu `LocalDate`.
Bên cạnh đó, chúng ta đã diễn đạt một số criteria ở mức trừu tượng của business requirement và tạo ra các `Specification` có thể thực thi được.
====

Sử dụng một specification trực tiếp với repository:

[source,java]
----
List<Customer> customers = customerRepository.findAll(isLongTermCustomer());
----

Specification trở nên có giá trị nhất khi được kết hợp (composed) với nhau:

[source,java]
----
MonetaryAmount amount = new MonetaryAmount(200.0, Currencies.DOLLAR);
List<Customer> customers = customerRepository.findAll(
  isLongTermCustomer().or(hasSalesOfMoreThan(amount))
);
----

[[specification-interfaces]]
== `Specification`, `UpdateSpecification`, `DeleteSpecification`

Interface javadoc:org.springframework.data.jpa.domain.Specification[] đã tồn tại từ lâu hơn nhiều và gắn với một loại query cụ thể (select, update, delete) theo đúng giới hạn của Criteria API.
Ba interface specification được định nghĩa như sau:

[tabs]
======
Specification::
+
====
[source,java,indent=0,subs="verbatim,quotes",role="primary"]
----
public interface Specification<T> {
  Predicate toPredicate(Root<T> root, CriteriaQuery<?> query,
            CriteriaBuilder builder);
}
----
====

UpdateSpecification::
+
====
[source,java,indent=0,subs="verbatim,quotes",role="secondary"]
----
public interface UpdateSpecification<T> {
  Predicate toPredicate(Root<T> root, CriteriaUpdate<T> update,
            CriteriaBuilder builder);
}
----
====

DeleteSpecification::
+
====
[source,java,indent=0,subs="verbatim,quotes",role="tertiary"]
----
public interface DeleteSpecification<T> {
  Predicate toPredicate(Root<T> root, CriteriaDelete<T> delete,
            CriteriaBuilder builder);
}
----
====
======

Đối tượng `Specification` có thể được tạo trực tiếp hoặc bằng cách tái sử dụng các instance `PredicateSpecification`, như trong ví dụ sau:

.Specification cho Customer
====
[source, java]
----
public class CustomerSpecs {

  public static UpdateSpecification<Customer> updateLastnameByFirstnameAndLastname(String newLastName, String currentFirstname, String currentLastname) {
    return UpdateSpecification.<Customer>update((root, update, criteriaBuilder) -> {
      update.set("lastname", newLastName);
    }).where(hasFirstname(currentFirstname).and(hasLastname(currentLastname)));
  }

  public static PredicateSpecification<Customer> hasFirstname(String firstname) {
    return (root, builder) -> {
      return builder.equal(root.get("firstname"), firstname);
    };
  }

  public static PredicateSpecification<Customer> hasLastname(String lastname) {
    return (root, builder) -> {
      // build query here
    };
  }
}
----
====

[[specification-fluent]]
== Fluent API

`JpaSpecificationExecutor` định nghĩa các fluent query method để thực thi query một cách linh hoạt dựa trên các instance `Specification`:

1. Cho `PredicateSpecification`: `findBy(PredicateSpecification<T> spec, Function<? super SpecificationFluentQuery<S>, R> queryFunction)`
2. Cho `Specification`: `findBy(Specification<T> spec, Function<? super SpecificationFluentQuery<S>, R> queryFunction)`

Cũng như các method khác, nó thực thi một query được suy ra (derived) từ một `Specification`.
Tuy nhiên, query function cho phép bạn kiểm soát các khía cạnh của việc thực thi query mà bạn không thể kiểm soát một cách linh hoạt bằng cách khác.
Bạn thực hiện điều này bằng cách gọi các intermediate method và terminal method khác nhau của `SpecificationFluentQuery`.

**Intermediate method**

* `sortBy`: Áp dụng thứ tự sắp xếp cho kết quả của bạn.
Gọi method này nhiều lần sẽ nối thêm từng `Sort` (lưu ý rằng `page(Pageable)` khi dùng một `Pageable` đã có sort sẽ ghi đè mọi thứ tự sort trước đó).
* `limit`: Giới hạn số lượng kết quả.
* `as`: Chỉ định type sẽ được đọc hoặc project sang.
* `project`: Giới hạn các property của query.

**Terminal method**

* `first`, `firstValue`: Trả về giá trị đầu tiên. `first` trả về `Optional<T>` hoặc `Optional.empty()` nếu query không trả về kết quả nào. `firstValue` là biến thể nullable của nó, không cần dùng `Optional`.
* `one`, `oneValue`: Trả về giá trị duy nhất. `one` trả về `Optional<T>` hoặc `Optional.empty()` nếu query không trả về kết quả nào. `oneValue` là biến thể nullable của nó, không cần dùng `Optional`.
Ném ra `IncorrectResultSizeDataAccessException` nếu tìm thấy nhiều hơn một kết quả khớp.
* `all`: Trả về toàn bộ kết quả dưới dạng `List<T>`.
* `page(Pageable)`: Trả về toàn bộ kết quả dưới dạng `Page<T>`.
* `slice(Pageable)`: Trả về toàn bộ kết quả dưới dạng `Slice<T>`.
* `scroll(ScrollPosition)`: Dùng scrolling (offset, keyset) để lấy kết quả dưới dạng `Window<T>`.
* `stream()`: Trả về một `Stream<T>` để xử lý kết quả dưới dạng stream thay vì một `Collection` đã materialize (xem xref:repositories/query-return-types-reference.adoc#return-type.stream[ngữ nghĩa của `Stream`]).
Stream này có trạng thái (stateful) và phải được đóng lại sau khi sử dụng.
* `count` và `exists`: Trả về số lượng entity khớp hoặc liệu có tồn tại kết quả khớp nào hay không.

NOTE: Intermediate method và terminal method phải được gọi bên trong query function.

.Dùng fluent API để lấy một `Page` đã được project, sắp xếp theo `lastname`
====
[source,java]
----
Page<CustomerProjection> page = repository.findBy(spec,
    q -> q.as(CustomerProjection.class)
          .page(PageRequest.of(0, 20, Sort.by("lastname")))
);
----
====

.Dùng fluent API để lấy kết quả cuối cùng trong số nhiều kết quả có thể có, sắp xếp theo `lastname`
====
[source,java]
----
Optional<Customer> match = repository.findBy(spec,
    q -> q.sortBy(Sort.by("lastname").descending())
          .first()
);
----
====
