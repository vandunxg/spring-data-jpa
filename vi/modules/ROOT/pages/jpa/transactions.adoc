[[transactions]]
= Transactionality

Theo mặc định, các method được kế thừa từ `CrudRepository` sẽ kế thừa transactional configuration từ javadoc:org.springframework.data.jpa.repository.support.SimpleJpaRepository[].
Đối với read operation, flag `readOnly` của transaction configuration được set thành `true`.
Tất cả các method còn lại được cấu hình bằng `@Transactional` thông thường để áp dụng default transaction configuration.
Các repository method được hỗ trợ bởi transactional repository fragment sẽ kế thừa transactional attribute từ fragment method tương ứng.

Nếu cần tinh chỉnh transaction configuration cho một trong các method được khai báo trong repository, hãy redeclare method đó trong repository interface, như sau:

.Custom transaction configuration cho CRUD
====
[source, java]
----
public interface UserRepository extends CrudRepository<User, Long> {

  @Override
  @Transactional(timeout = 10)
  public List<User> findAll();

  // Các khai báo query method khác
}
----
Việc này khiến method `findAll()` chạy với timeout 10 giây mà không có flag `readOnly`.
====

Một cách khác để thay đổi transactional behavior là sử dụng facade hoặc service implementation bao quát (thường là) nhiều repository. Mục đích của facade là định nghĩa transactional boundary cho các operation không phải CRUD. Ví dụ sau minh họa cách dùng facade cho nhiều repository:

.Sử dụng facade để định nghĩa transaction cho nhiều repository call
====
[source, java]
----
@Service
public class UserManagementImpl implements UserManagement {

  private final UserRepository userRepository;
  private final RoleRepository roleRepository;

  public UserManagementImpl(UserRepository userRepository,
    RoleRepository roleRepository) {
    this.userRepository = userRepository;
    this.roleRepository = roleRepository;
  }

  @Transactional
  public void addRoleToAllUsers(String roleName) {

    Role role = roleRepository.findByName(roleName);

    for (User user : userRepository.findAll()) {
      user.addRole(role);
      userRepository.save(user);
    }
  }
}
----
Ví dụ này khiến lời gọi `addRoleToAllUsers(…)` chạy bên trong một transaction (tham gia vào transaction hiện có hoặc tạo transaction mới nếu chưa có transaction nào đang chạy). Transaction configuration ở các repository lúc này bị bỏ qua, vì transaction configuration bên ngoài quyết định transaction thực tế được sử dụng. Lưu ý rằng phải kích hoạt `<tx:annotation-driven />` hoặc dùng `@EnableTransactionManagement` một cách tường minh để annotation-based configuration của facade hoạt động.
Ví dụ này giả định bạn đang dùng component scanning.

Lưu ý rằng lời gọi `save` không thực sự bắt buộc xét theo góc độ JPA, nhưng vẫn nên được giữ lại để nhất quán với repository abstraction do Spring Data cung cấp.
====

[[transactional-query-methods]]
== Transactional query methods

Các declared query method (bao gồm cả default method) không được áp dụng transaction configuration nào theo mặc định.
Để chạy các method đó trong transaction, hãy dùng `@Transactional` trên repository interface do bạn định nghĩa, như ví dụ sau:

.Sử dụng @Transactional trên query method
====
[source, java]
----
@Transactional(readOnly = true)
interface UserRepository extends JpaRepository<User, Long> {

  List<User> findByLastname(String lastname);

  @Modifying
  @Transactional
  @Query("delete from User u where u.active = false")
  void deleteInactiveUsers();
}
----
Thông thường, bạn sẽ muốn flag `readOnly` được set thành `true`, vì phần lớn query method chỉ đọc dữ liệu. Ngược lại, `deleteInactiveUsers()` sử dụng annotation `@Modifying` và override transaction configuration. Do đó, method này chạy với flag `readOnly` được set thành `false`.
====

[NOTE]
====
Bạn có thể dùng transaction cho các read-only query và đánh dấu chúng bằng cách set flag `readOnly`. Tuy nhiên, việc này không phải là một phép kiểm tra để đảm bảo bạn không trigger manipulating query (mặc dù một số database sẽ từ chối các statement `INSERT` và `UPDATE` bên trong read-only transaction). Thay vào đó, flag `readOnly` được propagate dưới dạng hint cho JDBC driver bên dưới để tối ưu performance. Hơn nữa, Spring còn thực hiện một số tối ưu trên JPA provider bên dưới. Ví dụ, khi dùng với Hibernate, flush mode được set thành `MANUAL` khi bạn cấu hình transaction là `readOnly`, khiến Hibernate bỏ qua dirty checking (một cải thiện đáng kể trên các object tree lớn).
====

[NOTE]
====
Mặc dù các ví dụ thảo luận việc dùng `@Transactional` trên repository, nhìn chung chúng tôi khuyến nghị khai báo transaction boundary khi bắt đầu một unit of work để đảm bảo tính nhất quán và transaction participation như mong muốn.
====
