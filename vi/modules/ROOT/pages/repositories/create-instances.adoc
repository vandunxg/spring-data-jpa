[[jpa.configuration]]
= Cấu hình

Phần này mô tả cách cấu hình Spring Data JPA thông qua một trong hai cách:

* "`<<jpa.java-config,Cấu hình dựa trên Annotation>>`" (Java configuration)
* "`<<repositories.create-instances.xml,Spring Namespace>>`" (XML configuration)

[[jpa.java-config]]
== Cấu hình dựa trên Annotation
Spring Data JPA repositories support có thể được kích hoạt thông qua cả JavaConfig và một custom XML namespace, như ví dụ sau:

.Spring Data JPA repositories sử dụng JavaConfig
====
[source, java]
----
@Configuration
@EnableJpaRepositories
@EnableTransactionManagement
class ApplicationConfig {

  @Bean
  public DataSource dataSource() {

    EmbeddedDatabaseBuilder builder = new EmbeddedDatabaseBuilder();
    return builder.setType(EmbeddedDatabaseType.HSQL).build();
  }

  @Bean
  public LocalContainerEntityManagerFactoryBean entityManagerFactory() {

    HibernateJpaVendorAdapter vendorAdapter = new HibernateJpaVendorAdapter();
    vendorAdapter.setGenerateDdl(true);

    LocalContainerEntityManagerFactoryBean factory = new LocalContainerEntityManagerFactoryBean();
    factory.setJpaVendorAdapter(vendorAdapter);
    factory.setPackagesToScan("com.acme.domain");
    factory.setDataSource(dataSource());
    return factory;
  }

  @Bean
  public PlatformTransactionManager transactionManager(EntityManagerFactory entityManagerFactory) {

    JpaTransactionManager txManager = new JpaTransactionManager();
    txManager.setEntityManagerFactory(entityManagerFactory);
    return txManager;
  }
}
----
====
NOTE: Bạn phải tạo `LocalContainerEntityManagerFactoryBean` chứ không tạo trực tiếp `EntityManagerFactory`, vì `LocalContainerEntityManagerFactoryBean` còn tham gia vào cơ chế exception translation bên cạnh việc tạo `EntityManagerFactory`.

Configuration class ở trên thiết lập một embedded HSQL database bằng `EmbeddedDatabaseBuilder` API của `spring-jdbc`. Sau đó Spring Data thiết lập một `EntityManagerFactory` và dùng Hibernate làm persistence provider mẫu. Infrastructure component cuối cùng được khai báo ở đây là `JpaTransactionManager`. Cuối cùng, ví dụ này kích hoạt Spring Data JPA repositories bằng annotation `@EnableJpaRepositories`, về cơ bản mang các attribute giống như XML namespace. Nếu không cấu hình base package, nó sẽ dùng package chứa configuration class.

[[repositories.create-instances.xml]]
== Spring Namespace

Module JPA của Spring Data chứa một custom namespace cho phép định nghĩa repository bean. Namespace này cũng chứa một số tính năng và element attribute đặc thù cho JPA. Nhìn chung, JPA repositories có thể được thiết lập bằng element `repositories`, như ví dụ sau:

.Thiết lập JPA repositories bằng namespace
====
[source, xml]
----
<?xml version="1.0" encoding="UTF-8"?>
<beans xmlns="http://www.springframework.org/schema/beans"
  xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xmlns:jpa="http://www.springframework.org/schema/data/jpa"
  xsi:schemaLocation="http://www.springframework.org/schema/beans
    https://www.springframework.org/schema/beans/spring-beans.xsd
    http://www.springframework.org/schema/data/jpa
    https://www.springframework.org/schema/data/jpa/spring-jpa.xsd">

  <jpa:repositories base-package="com.acme.repositories" />

</beans>
----
====

TIP: Nên dùng JavaConfig hay XML? XML là cách Spring được cấu hình từ thời xưa. Trong thời đại Java phát triển nhanh hiện nay, với record type, annotation và nhiều tính năng khác, các dự án mới thường dùng càng nhiều pure Java càng tốt. Dù chưa có kế hoạch loại bỏ XML support ngay, một số tính năng mới nhất CÓ THỂ không khả dụng qua XML.

Khi dùng element `repositories`, nó kích hoạt persistence exception translation cho tất cả bean được annotate bằng `@Repository`, để các exception do JPA persistence provider ném ra được convert sang hierarchy `DataAccessException` của Spring.

[[jpa.namespace.custom-namespace-attributes]]
=== Custom Namespace Attributes
Ngoài các attribute mặc định của element `repositories`, JPA namespace còn cung cấp thêm các attribute để bạn kiểm soát chi tiết hơn việc thiết lập repositories:

.Custom JPA-specific attributes của element `repositories`
[options = "autowidth"]
|===============
|`entity-manager-factory-ref`|Wire tường minh `EntityManagerFactory` sẽ được dùng với các repositories được phát hiện bởi element `repositories`. Thường dùng khi ứng dụng có nhiều bean `EntityManagerFactory`. Nếu không cấu hình, Spring Data sẽ tự động tìm bean `EntityManagerFactory` có tên `entityManagerFactory` trong `ApplicationContext`.
|`transaction-manager-ref`|Wire tường minh `PlatformTransactionManager` sẽ được dùng với các repositories được phát hiện bởi element `repositories`. Thường chỉ cần thiết khi có nhiều transaction manager hoặc nhiều bean `EntityManagerFactory` được cấu hình. Mặc định dùng `PlatformTransactionManager` duy nhất được định nghĩa trong `ApplicationContext` hiện tại.
|===============

NOTE: Spring Data JPA yêu cầu phải có một bean `PlatformTransactionManager` tên là `transactionManager` nếu không định nghĩa tường minh `transaction-manager-ref`.

[[jpa.bootstrap-mode]]
== Bootstrap Mode

Mặc định, Spring Data JPA repositories là các Spring bean thông thường.
Chúng có scope singleton và được khởi tạo eager.
Trong quá trình startup, chúng đã tương tác với JPA `EntityManager` để phục vụ việc verification và phân tích metadata.
Spring Framework hỗ trợ khởi tạo JPA `EntityManagerFactory` trong một background thread vì quá trình này thường chiếm một phần đáng kể thời gian startup của ứng dụng Spring.
Để tận dụng hiệu quả việc khởi tạo nền này, chúng ta cần đảm bảo JPA repositories được khởi tạo càng muộn càng tốt.

Từ Spring Data JPA 2.1, bạn có thể cấu hình `BootstrapMode` (thông qua annotation `@EnableJpaRepositories` hoặc XML namespace) với các giá trị sau:

* `DEFAULT` (mặc định) -- Repositories được khởi tạo eager trừ khi được annotate tường minh bằng `@Lazy`.
Việc lazify này chỉ có tác dụng nếu không có client bean nào cần một instance của repository, vì điều đó sẽ yêu cầu khởi tạo repository bean.
* `LAZY` -- Ngầm định khai báo tất cả repository bean là lazy và cũng khiến các lazy initialization proxy được tạo ra để inject vào client bean.
Điều đó có nghĩa là repositories sẽ không được khởi tạo nếu client bean chỉ đơn giản lưu instance vào một field mà không sử dụng repository trong lúc khởi tạo.
Repository instance sẽ được khởi tạo và verify khi có tương tác đầu tiên với repository.
* `DEFERRED` -- Về bản chất hoạt động giống `LAZY`, nhưng trigger việc khởi tạo repository để phản hồi một `ContextRefreshedEvent`, để repositories được verify trước khi ứng dụng khởi động hoàn tất.

[[jpa.bootstrap-mode.recommendations]]
=== Khuyến nghị

Nếu bạn không dùng JPA bootstrap bất đồng bộ (asynchronous), hãy giữ nguyên bootstrap mode mặc định.

Trong trường hợp bạn bootstrap JPA bất đồng bộ, `DEFERRED` là lựa chọn mặc định hợp lý vì nó đảm bảo Spring Data JPA bootstrap chỉ chờ việc thiết lập `EntityManagerFactory` nếu bản thân việc đó mất nhiều thời gian hơn việc khởi tạo tất cả các application component khác.
Dù vậy, nó vẫn đảm bảo repositories được khởi tạo và validate đúng cách trước khi ứng dụng báo hiệu đã sẵn sàng.

`LAZY` là lựa chọn khá tốt cho các kịch bản testing và local development.
Khi bạn đã khá chắc chắn rằng repositories có thể bootstrap đúng cách, hoặc trong trường hợp bạn đang test các phần khác của ứng dụng, việc chạy verification cho tất cả repositories có thể làm tăng thời gian startup một cách không cần thiết.
Điều tương tự cũng áp dụng cho local development, khi bạn chỉ truy cập các phần của ứng dụng cần khởi tạo một repository duy nhất.
